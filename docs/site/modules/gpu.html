Modules / gpu.smk

Run reliably on one NVIDIA GPU

The GPU module records hardware readiness and completion. The shell launcher adds resilient sequencing across incompatible embedder environments.

Rule: gpu_preflight

Hardware check

Output: artifacts/gpu/preflight.json.

Checks: CUDA visibility, device name, memory, and configured minimum memory. The launcher forces this rule every invocation so a report copied from another machine cannot bypass local validation.

Rule: gpu_results

This is strict completion. It requires preflight, evaluation, reconstruction predictions, training curves, training plots, and every enabled figure/source table for all requested embedders. Only then does it write results_complete.json.

Rule: gpu_embedder_result

This per-embedder goal requires core model outputs and five modular analysis metric tables. The launcher invokes it separately for each active method so an analysis failure is isolated.

Rule: gpu_report

This rule deliberately has no scientific input dependencies. When forced at the end, its script inventories expected paths and writes results_report.json and results_report.csv even if another job failed. It distinguishes fully complete, core-complete/analysis-incomplete, and failed runs, preserves available NLL/perplexity/counts, and points to expected logs.

Why run_gpu.sh invokes Snakemake repeatedly

Snakemake may create all required Conda environments before executing jobs in a combined graph. One broken optional environment could then prevent independent methods from starting. The launcher instead loops over embedders and calls Snakemake separately. A failure is recorded, later embedders are still attempted, and valid outputs are reusable on rerun.

Serialization and prefetch overlap

The profile exposes one gpu resource, so heavy jobs remain sequential. The launcher may prefetch a future embedder’s weights/environment in a background process while the current embedder computes, using a separate Conda package cache to avoid concurrent-cache corruption. It never overlaps two GPU scientific jobs.

Reading a failure

Start with results_report.json. Identify the embedder and first missing stage, then open the named file under artifacts/logs/ or .snakemake/log/. Fix the smallest failing layer and rerun the identical launcher command; do not delete valid artifacts or collapse environments.
