Modules / standardize.smk

Convert raw metadata into a stable schema

Standardization is an adapter boundary: it translates SAbDab2-specific names and conventions into columns every downstream module understands.

Rule: standardize

Input: the fetch readiness marker.

Output: artifacts/data/sabdab2_v<version>/standardized/standardized.csv.

Script: selected from a registry; currently standardize_sabdab2.py.

Environment: process.yaml.

Why an adapter is useful

Raw datasets disagree about column names, chain notation, missing values, and split labels. If embedding and training scripts read raw columns directly, adding another dataset would require edits everywhere. The standardizer concentrates dataset knowledge in one script.

Core output columns

ColumnMeaning
idStable record identifier, used in filenames.
pdb_pathPath to the corresponding mmCIF structure.
antigen_chainsOne or more chain identifiers belonging to the antigen.
expected_heavy_seqDataset-provided heavy variable-region sequence, used as the prediction target/provenance.
expected_light_seqDataset-provided light sequence.
expected_ag_seqDataset-provided antigen sequence or sequences.
splitSource train/test assignment.
ab_ag_clusterAntibody–antigen relationship group used to prevent split leakage.

Heavy-chain scope

The standardizer deliberately maps the heavy variable-domain field into the modeling target. A longer full-heavy sequence may be retained only as provenance. This is why the project predicts the resolved variable heavy sequence rather than only CDR3 or an entire secreted antibody molecule.

Dataset registry

_STANDARDIZERS maps dataset.name to its adapter script. An unknown name raises an explanatory parse error. To add a dataset safely, implement the same output contract and register it here; downstream modules should not change.

What standardization does not do

It does not apply final inclusion filters, parse backbone-complete resolved residues, or create validation splits. Those decisions belong to the next module so they are uniform across datasets.

Common mistakes

  • Confusing expected sequences from metadata with resolved sequences actually present in the structure.
  • Dropping cluster columns needed for leakage-safe splitting.
  • Changing identifier construction after embeddings already exist.
  • Putting dataset-specific conditions into generic downstream scripts.
