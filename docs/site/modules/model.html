Modules / model.smk

Train, evaluate, reconstruct, and generate

One parameter-matched MANGO model is trained per antigen representation. Every operation uses antigen plus a learned output selector; no antibody sequence is conditioning input.

What the model learns

The model is autoregressive: it estimates the probability of the next target-chain token from projected antigen tokens, a learned heavy/light selector, and earlier target tokens. During training, the known target supplies shifted previous-token/next-token pairs through teacher forcing; it is never part of the conditioning prefix.

A direct projection maps each antigen representation into the shared decoder width. Because decoder architecture and training settings are fixed across runs, differences are intended to reflect antigen representation.

Rule: train_model

Training contract

Inputs: processed target records, train/validation antigen tensors for the run’s tag, and embedder configuration.

Outputs: best/latest checkpoints, model configuration, epoch metrics, iteration-level training curve CSV and PNG, and the complete run configuration.

Script/environment: train_mango.py in model.yaml; requests one GPU.

The training loop shuffles training records reproducibly per epoch, accumulates token loss, updates parameters, and evaluates on validation after each epoch. The best checkpoint is the one with the lowest validation loss. Patience controls early stopping. training_curve.csv is flushed during training and its PNG is refreshed atomically, so it can be viewed safely while training continues.

Retraining policy

When model.retrain is false, expensive training inputs are marked ancient(): their modification times do not automatically retrigger an existing checkpoint, though missing outputs are still built. This is execution policy, not model identity. A deliberate retrain can be forced.

Rule: evaluate_model

Evaluation loads the best checkpoint and computes token-level negative log-likelihood (NLL), perplexity, example count, and token count for train, validation, and test. It does not change parameters. The JSON output is the source for Figure 1. Reporting train and test together helps reveal generalization gaps.

Rule: predict_model

Prediction performs one held-out reconstruction per configured test record. The reference sequence for the requested output chain is used only for comparison. The CSV records generated sequences and status. Reconstruction is a sanity/evaluation task; it is different from sampling many new designs.

Rule: generate_designs

Generation creates multiple de novo requested-chain sequences for one (run, target) pair. Targets come from the diverse, held-out set chosen after the process checkpoint. The rule loads only the target antigen tensor, model configuration, and best checkpoint. Sampling settings and output chain type come from configuration.

No antibody prompt: generation begins from projected antigen tokens, the output selector, and BOS. Every output row records chain type, target, index, sequence, length, and status.

Common mistakes

  • Reading low training NLL as proof of held-out performance.
  • Using test data to choose the best checkpoint; validation must serve that role.
  • Treating each sampled sequence as independent biological evidence.
  • Changing model hyperparameters for one embedder and attributing the result only to antigen representation.
  • Assuming smoke generations are full scientific results; smoke settings deliberately truncate and reduce work.
