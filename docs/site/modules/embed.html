Modules / embed.smk

Represent the antigen and light-chain context

Embedding turns biological inputs into numeric tensors. MANGO varies only the antigen tensor; the antibody-side light-chain tensor is held constant.

Shared tensor contract

Antigen: embeddings/antigen/<tag>/<split>/<id>.pt.

Antibody context: embeddings/antibody/ablang2_light_only/<split>/<id>.pt.

Metadata: each embedding family has embedder_config.json; tensors include shape, length, dimension, chain/source metadata, and the embedding matrix.

The experimental separation

The antigen matrix is the independent variable. The AbLang2 context is constant. The latter encodes a paired format with the heavy position masked and the observed light sequence present. No heavy residues are saved in the context tensor.

Rule families

Configuration rules

embedder_config and antibody_embedder_config write JSON descriptions. Model training reads the antigen description to determine feature dimension and saves it with the run.

Weight rules

AbLang2 and ProteinMPNN have explicit download rules. ESM-2, ESM-IF, and ESM3 use prefetch scripts that load upstream packages, cache public models, validate GPU/gating requirements, and write small marker JSON files. PyRosetta’s rule validates installed licensed assets rather than downloading license material.

Exact rule nameResponsibility

prefetch_esm2_weightsPopulate and verify the ESM-2 cache.

Per-record rules

Each embed_antigen_* rule writes the same path pattern and is restricted to matching embedder tags. Sequence methods read records.csv; structure methods also require the record’s mmCIF file. embed_antibody_ablang2 reads the light sequence and AbLang2 weights.

The exact antigen rule names are embed_antigen_one_hot, embed_antigen_biopython, embed_antigen_pyrosetta_pre, embed_antigen_esm2, embed_antigen_esm3, embed_antigen_esmif, embed_antigen_proteinmpnn, and the deferred embed_antigen_afm. Aggregate rules embed_antigen, embed_antibody, and embed request the complete active output sets.

Batch rules

GPU mode uses batch_antigen_* and batch_antibody_ablang2. embed_batch.py loads each implementation dynamically, keeps a large model in memory, loops over records, validates/reuses existing outputs, and writes a completion marker only when the batch is valid. The scientific tensor format is unchanged.

The exact antigen batch rules are batch_antigen_one_hot, batch_antigen_biopython, batch_antigen_pyrosetta_pre, batch_antigen_esm2, batch_antigen_esm3, batch_antigen_esmif, and batch_antigen_proteinmpnn. The light-context batch is batch_antibody_ablang2. The weights aggregate rule requests every weight needed by the active tags.

Chain boundaries and lengths

Antigens may contain more than one chain. Embedders preserve boundaries using chain metadata and, where the representation supports it, separator rows/tokens. A tensor length L is therefore related to resolved residues plus any representation-specific separators. Cross-attention allows antigen and light tensors to have different lengths.

Dependency isolation

Each method has its own Conda environment. This is essential: packages can expose modules with the same name but incompatible APIs, and PyRosetta has separate distribution/licensing constraints. Installing everything into one environment is not a supported fix.

GPU resource behavior

Learned and heavy structure encoders declare gpu=1. The single-GPU profile provides only one such resource, so they run sequentially. CPU baselines may run without that resource but still obey the batch embedder_slot limit.

Validation and common mistakes

  • Do not feed resolved_H_seq to any embedding used for conditioning.
  • Do not compare representations built from different residue sets without documenting the mismatch.
  • Do not confuse ProteinMPNN as used here (an antigen encoder) with MANGO’s heavy-chain generator.
  • Do not silently fall back to random weights or CPU when GPU execution is required.
  • Do not remove chain separators or merge multiple antigen chains without recording boundaries.
