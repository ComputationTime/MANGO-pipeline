Analysis / cohorts.smk

Select a fair generated-sequence cohort

A cohort is the fixed set of generated sequences sent to multiple analysis tools. Selecting it once prevents each figure from comparing a different sample.

Rule: analysis_cohort

Inputs: every designs.csv for one trained run across the diverse generation target set, plus records.csv.

Output: artifacts/analysis/<run>/cohort.csv.

Parameters: designs per target and deterministic seed.

Script/environment: select_cohort.py in analysis_core.yaml.

Selection algorithm

  1. Concatenate the design tables for the run.
  2. Keep rows whose generation status is successful.
  3. Join the target’s cognate light sequence from the processed records.
  4. Compute a stable SHA-256 selection key from the cohort seed, target identifier, and design index.
  5. Sort by that key rather than input row order.
  6. Take the configured number per target, or all successful designs when no cap is set.
  7. Write provenance columns including split, target, sequence, selection key, seed, and rank.

Fairness across antigen representations

The key excludes the embedder tag, so design index 7 for a target receives the same rank in every model’s table. Generated sequences differ, but the sampling positions and target coverage match. The generation targets themselves were selected one per held-out cluster before any cap.

Failure behavior

The script validates required columns and successful rows. It does not fill a model’s missing design with a different index from another model without recording the resulting cohort. Downstream source tables retain identifiers so imbalance can be audited.
