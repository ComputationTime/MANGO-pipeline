Modules / fetch.smk

Fetch the SAbDab2 source dataset

The fetch module obtains the raw antibody–antigen structures and split metadata. It does not interpret biology or choose records.

Rule: fetch_sabdab2

Inputs: none as files; URL, dataset version, artifact root, and expected split filename come from configuration.

Output: artifacts/data/sabdab2_v<version>/.sabdab2_ready.

Script: workflow/scripts/fetch_sabdab2.py.

Environment: workflow/envs/fetch.yaml.

What SAbDab2 provides

SAbDab2 is the source of antibody–antigen complex metadata, predefined source splits, and macromolecular Crystallographic Information File (mmCIF) structures. The configured antigen-aware table is abag_split.csv.

Step by step

  1. Create a versioned dataset directory under artifacts/data.
  2. Download splits.tar.gz from the configured Zenodo record. A partial sibling file is used so interruption cannot masquerade as success.
  3. If the server supports byte ranges, resume an interrupted transfer; otherwise restart safely.
  4. Inspect archive entries and reject absolute paths, parent-directory traversal, symbolic links, and hard links.
  5. Extract into a temporary staging directory and move the discovered splits_final directory into place.
  6. Verify that the configured split table exists, then write the readiness marker.

Why depend on a marker?

The archive contains thousands of files. Listing every structure as a Snakemake output would create a huge graph. The marker is compact evidence that extraction and validation completed. The next module depends on it and reads the split table from the known versioned location.

Idempotence and recovery

Idempotent means repeating an operation produces the same state without duplicating work. If splits_final already exists, the script does not redownload. If only the archive exists, it reuses it. If a download was interrupted, it keeps a .partial file and resumes when possible.
