Run and inspect the project safely

The supported cloud interface is run_gpu.sh. Direct Snakemake targets are useful for development and opt-in modules, but they do not replace the launcher’s failure isolation.

Before changing execution logic

Read docs/cloud_gpu_setup.md. Confirm an NVIDIA GPU is visible, disk and memory are sufficient, Conda and Git exist, and outbound HTTPS works. Do not manually merge all dependencies into a global environment.

First command

./run_gpu.sh smoke

Smoke mode uses a tiny, cluster-preserving subset and reduced settings. Its purpose is to confirm data → embedding → model → analysis plumbing. Smoke metrics are not scientifically interpretable.

After smoke

Allow the launcher to attempt every embedder even if one fails. Read artifacts/gpu/results_report.json and follow its log paths. Once the outcome is understood and fixed, rerun the identical command. Only then run:

./run_gpu.sh study

Useful direct targets

Command targetWhat it requests
fetchRaw dataset staged and validated.
processFinal processed records table.
embedAntigen and light-context tensors for active embedders.
trainBest checkpoint for each active embedder.
inferenceEvaluation plus held-out reconstruction.
generateExplicit de novo generation for the diverse held-out set.
analysisEnabled standard figures and source CSVs.

Opt-in structure confidence

.snakemake/gpu-driver/bin/snakemake -s workflow/Snakefile \
  --profile workflow/profiles/gpu \
  --configfile config/gpu.yaml config/structure.yaml \
  structure_confidence

This target is separate from smoke/study. It folds generated H+L+antigen complexes with Boltz and Chai. The first environment/model download is large. Single-sequence mode is the default; external multiple-sequence alignment service use must be explicitly enabled.

Configuration overlays

config/config.yaml is the base state. Later --configfile overlays extend or replace selected values. gpu.yaml activates supported methods and batch embeddings; smoke.yaml/small.yaml bound work; optional overlays add gated methods. config/structure.yaml enables Figure 2 and local structural predictors.

Dry runs and validation

bash -n run_gpu.sh
python -m unittest discover -s tests -v
snakemake --lint
snakemake --sdm conda --cores 1 --dry-run

A dry run builds the dependency graph without running jobs. Some tests require a Snakemake Conda environment because host Python intentionally lacks scientific packages such as PyTorch.

Logs and resumability

Rule logs live under artifacts/logs/; Snakemake’s own logs live under .snakemake/log/. Outputs are atomic or have readiness markers where needed. Rerunning reuses valid files and per-record embeddings. Do not use destructive Git or filesystem commands to “clean” a failure before identifying its layer.

Credentials and generated data

Tokens such as HF_TOKEN belong in environment variables, never committed YAML, logs, or commands saved to Git. Generated data, environments, caches, weights, and results belong under .snakemake/ or artifacts/.
